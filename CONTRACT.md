# ANUBIS Contract v1

This document defines **Contract v1**: the deterministic behavior and byte-for-byte output rules for ANUBIS.

## Non-negotiables

- Evidence is **deterministically ordered by ID** (ascending).
- The checksum algorithm and its inputs are a **stable public contract**.
- Outputs are **byte-for-byte identical** across OS/CPU/toolchains **for the same inputs and CLI arguments**.
- The core engine is reentrant and has **no global shared state**.

## Fixed constants (Contract v1)

- `SCALAR_PHI = 1.61803398875`
- `VECTOR_WEIGHTS = [3.0, 6.0, 9.0]` selected by `weight_idx = id % 3`
- Cluster thresholds:
  - `STABLE` if `momentum < 10.0`
  - `ACTIVE` if `10.0 <= momentum < 50.0`
  - `HIGH_ENTROPY` if `momentum >= 50.0`
- Default sampling: `sample_every = 5000` (configurable by CLI; the chosen value becomes part of the output contract for that run)

## Canonical tables (LUT)

To guarantee cross-platform/toolchain stability, the engine uses precomputed lookup tables for:

- `state` (u8 in range 0..=9)
- `cluster` (enum)
- `momentum_q4` (fixed-point integer, scaled by 10,000)

The canonical tables are embedded in source and **must not be regenerated** unless the contract version is bumped and golden vectors are updated.

## Checksum (stable contract)

For each byte at index `id`:

- `state = STATE_TABLE[weight_idx][byte]`
- `term = (state as u64).wrapping_add(id as u64)`
- checksum is the XOR reduction over all terms:
  - `checksum = term_0 ^ term_1 ^ ... ^ term_{n-1}`

Checksum is independent of thread count and IO strategy (mmap vs buffered).

## Evidence units

Evidence is emitted when:

- `sample_every != 0` and `id % sample_every == 0`

Fields:

- `id` (byte offset)
- `cluster` (`STABLE` | `ACTIVE` | `HIGH_ENTROPY`)
- `state` (0..9)
- `momentum_q4` (integer) and text rendering derived from it

## Text output (byte-for-byte contract)

- Text output is generated from integers and fixed strings only.
- Momentum is printed as a fixed-point decimal with 4 digits after the dot:
  - `momentum_q4 = int_part * 10_000 + frac_part`
  - printed as `"{int_part:>7}.{frac_part:04}"`
- All line breaks are `\\n`.

## JSON output (versioned schema)

JSON output is a single object with stable field order and stable whitespace, generated by a manual renderer (no dependency-controlled formatting).

- `schema_version` (u32) and `contract_version` (u32)
- `input` (string label as provided by CLI)
- `mode` (`"mmap"` or `"read"`)
- `sample_every`
- `processed_bytes`
- `checksum_hex` (fixed-width, `0x` + 16 uppercase hex)
- `evidence` (array, sorted by `id`)
